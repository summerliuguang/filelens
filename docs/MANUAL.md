# FileLens 使用手册

> 适用版本：v0.5.0 ｜ 平台：Linux（deb/rpm/AppImage）、Windows（NSIS 安装包）

## 1. FileLens 是什么

FileLens 在你的电脑上找出**内容完全相同**的重复文件（BLAKE3 完整哈希确认），并给出**相似**照片/文档候选供人工比对。它帮助你在确认后把多余的副本移入可恢复的应用回收站或永久删除，从而释放磁盘空间。

**安全承诺**：

- 扫描只读取文件，不修改任何数据；
- 任何删除前都要求：文件属于精确重复组 + 你已人工标记 + 未命中保护规则 + 当前内容与索引哈希一致（删除前重新哈希比对）；
- 移入回收站后可随时恢复；恢复时若原位置已有文件会拒绝执行，绝不覆盖；
- 每一次移入/恢复/删除都记录在操作历史中，可追溯。

## 2. 安装与启动

### 桌面应用

- **Linux**：安装 `FileLens_0.5.0_amd64.deb`（`sudo dpkg -i`，必须用绝对路径）或 rpm 包；或使用 AppImage（`chmod +x` 后直接运行）。
- **Windows**：运行 NSIS 安装包（FileLens_0.5.0_x64-setup.exe）。

首次启动会自动在本地创建 SQLite 数据库与应用回收站目录，零配置即可使用；「扫描来源」为空时会显示三步引导；重启后自动打开上次的项目。

### 从源码构建（开发者）

```bash
npm install
npm run tauri build     # 桌面安装包（唯一有效的构建方式）
npm run tauri dev       # 开发调试
```

> ⚠️ 必须用 `npm run tauri build`。直接 `cargo build` 产出的二进制不含前端资产，运行时白屏且无任何编译报错。

从 Linux 交叉编译 Windows 安装包：

```bash
npm run tauri build -- --bundles nsis --runner cargo-xwin --target x86_64-pc-windows-msvc
```

前置：`nsis lld llvm` 已安装、`rustup target add x86_64-pc-windows-msvc`、`cargo install cargo-xwin`。

## 3. 快速上手（三步）

1. **添加扫描目录**：左侧导航「扫描来源」→ 输入路径或点击「选择目录」。
2. **开始扫描**：点击「开始增量扫描」。进度横幅显示已处理数量、速度与预计剩余时间；正在全量哈希大文件时还会显示文件名与本次扫描累计哈希字节（大文件不会表现为进度停滞）；可随时取消，已建立的索引保留。启动时默认会用已保存目录自动增量扫描（可在设置关闭）。
3. **审核并处理**：左侧「重复审核」查看重复组 → 点击文件可预览 →「标记删除」→ 组内出现「处理本组已标记副本」→ 选择「移入回收站（可恢复）」或「直接永久删除」。

处理完成后可在「应用回收站」恢复文件，在「操作历史」核对全部记录。

## 4. 界面指南（十个页面）

左侧导航栏固定不随内容滚动；顶部品牌区的「«」按钮可把侧栏收起为图标栏（再点「»」展开），收起状态会被记住。窄窗口下侧栏自动变为顶部横条。

### 概览
索引健康度一览：待审核副本数、可释放空间、已索引文件数、回收站文件数，以及下一步行动入口。

### 扫描来源
管理扫描根目录（多个目录会**全局互相比较**）。应用回收站和 `.git`、`node_modules`、`$RECYCLE.BIN` 自动排除。

### 重复审核（核心工作区）
- **筛选栏**：按路径关键字（回车应用）、最小文件大小、排序方式（大小/副本数/路径）筛选；显示匹配总组数，「加载更多」翻页。
- **重复组**：每组显示哈希、文件数、单文件大小；每行有缩略图（点击放大预览）、文件名、完整路径、修改时间。互为硬链接（同一物理文件的多个名字）的成员显示「硬链接」徽章；此时删除副本不会释放空间，界面会明确提示。
- **智能标记**：每组可一键「保留最新 / 保留最旧 / 保留最短路径」，自动标记其余副本。
- **跨组批量**：筛选栏可选择保留策略后「全部组智能标记」（作用于筛选命中的**所有**分组，不止已加载页），核对后用「回收全部已标记」把所有已标记副本作为一个批次统一移入回收站；受保护路径在任何情况下都不会被标记。
- **两步删除**：「标记删除」只是标记；组内出现「处理本组已标记副本」后才真正执行，弹窗提供三种处理方式——「移入回收站（可恢复）」「转为硬链接（无损去重）」「直接永久删除」。受保护文件显示「受保护」且不可标记。
- **硬链接去重**：把已标记副本替换为保留副本的硬链接——所有路径原样保留、程序无感知，重复内容立即释放。跨盘副本、受保护副本、内容已变化的副本会自动跳过并在结果中报告；该操作不经过回收站（保留副本即安全网），记录在操作历史中可查。
- **大文件提示**：超过 1 GB 的文件，移入回收站会先复制一份（耗时且占双倍空间），界面会建议直接删除。
- **导出报告**：点击「导出报告（CSV）」选择保存位置，导出当前全部重复组成员（哈希、路径、大小、修改时间、审批状态），适合清理前留档。

### 照片检测：重复 / 相似
页面顶部可切换两个视图：

- **扫描与识别**：文件被重命名或移动到其他位置后，下次扫描会通过 NTFS 文件引用号（Windows）/ 设备与 inode（Linux）识别出"还是那个文件"，直接继承哈希与指纹，不需要重新计算；设置页的「实时监控扫描目录」开启后，目录变化静置约三秒自动增量扫描。
- **重复照片**：双指纹完全一致（dHash 0/64 且 pHash 0/64）的候选，通常是同一张照片的复制副本（字节不同，复制时 EXIF 等信息略有变化）。字节级完全相同的副本不在此列——它们属于「重复审核」的精确重复。指纹仍有极小误判可能，因此页面会**自动在后台对每对候选做逐像素校验**，只有确认完全一致的才会出现在列表里；校验进度与被排除的相似候选数显示在页头。视图内还有两种查看模式：
  - **重复图片**（默认）：逐对列出，不同地方有同一张图片；
  - **重复目录**：把跨目录的重复照片按「目录对」分组、两列对照显示。每一列上方有自己的目录头（目录名、张数、体积，以及「移除这一侧」「用对侧替换本侧」两个按钮），按钮就在它所属的那一列正上方，不会认错侧；移除任一侧，副本都保留在对侧。组头上的「合并到一侧」把两侧重复照片集中到一个目录：先选**目标文件夹**（左侧 / 右侧 / 其他位置——可选现有目录，或输入新路径自动创建），再配置**保留条件**决定每对照片谁被移动过去、谁被回收。保留条件按优先级从上到下判断，第一个能分出胜负的条件生效，可用 ↑↓ 调整顺序、可勾选启停：**前缀匹配**（自动识别 IMG、Screenshot、微信图片等命名开头，默认勾选常见的相机/截图命名，可自定义）、**EXIF 拍摄时间**（有拍摄信息的一份优先；都有时保留更早的原图）、**分辨率较高**（保留像素尺寸更大的一份，默认关闭，可开启并排序）、**时间较新**（保留修改时间较晚的一份）、**优先指定目录**（无条件偏向某一侧）。没有条件能分出胜负时，保留目标文件夹里已有的那张。目录里不属于重复的照片不受影响，全部处理成功后被清空的来源目录会自动删除。
同一目录内部的对不进入此模式，请切回「重复图片」查看。
- **相似照片**：dHash 差异 1–4/64 且 pHash 差异 ≤阈值/64 的高置信度相似候选（双重感知指纹确认，多为重压缩或缩放后的同源照片）；阈值默认 10，可在设置页调整（4–20）。

两个视图共用同一套工具：

- **大图行**：每对候选并排显示两张大图，右侧列出文件名、大小、修改时间与建议保留提示。
- **并排放大对比**：点击任意一张缩略图，两张照片会以全尺寸并排展示，方便逐细节比对；在「重复照片」视图里弹窗顶部会再次逐像素校验并给出结论；Esc 或「关闭」返回。
- **按目录筛选**：候选来自多个目录时，右上角可按目录筛选；选中目录后可「回收该目录全部候选」，把这些候选作为一个批次移入应用回收站（可恢复）——若某一对的两张都在该目录，两张都会移入；移动前逐张校验保护规则与内容。
- 勾选后可批量移入回收站或删除——同样走保护规则与内容校验，**仅人工确认，无自动清理**。

### 相似文档
TXT/Markdown/CSV/JSON/XML/HTML 的文本近似候选（SimHash 差异 ≤8/64），显示每条路径的「定位」（在文件管理器中显示）与「打开」（系统程序）按钮。同样仅供人工判断。

### 检测能力
当前版本支持的检测项与未接入项的如实清单（音频/视频指纹未启用，不会以低质量算法替代）。

### 清理工具
两类「没有内容」的候选的一键清理入口（数据来自上一次扫描，可用「重新检查」刷新）：

- **空文件夹**：扫描发现的完全为空的目录。删除时会逐个**重新确认仍然为空**，扫描根目录、受保护目录、已消失或不再为空的目录自动跳过并逐条提示；文件夹删除不可恢复（但本来就是空的），每次删除都记录在案。
- **零字节文件**：0 字节的文件，不占空间但会污染重复列表。勾选后走标准安全链**移入应用回收站**（可恢复）。

### 应用回收站
- 从审核队列移入的副本，带原位置、移入时间；同一次批量操作产生的文件按「批次」分组展示（批次头显示操作时间与文件数）；侧栏角标显示数量。页头显示回收站实际占用。
- 「恢复原位置」带回单个文件（不覆盖已有文件）；批次头上的「恢复整批」一次性恢复该批全部文件——原位置被占用或校验失败的文件会逐条跳过并在结果中提示；批次头上还有「永久删除整批」（二次确认，删除后无法恢复）；「永久删除」「清空回收站」「清理过期文件」均需二次确认。
- 超过保留期（默认 30 天）的文件在**扫描结束时自动清理**，完成消息会明确报告清理数量；填 0 表示不自动清理。设置了「容量提醒上限」后，实际占用超过上限时页面顶部会显示提醒横幅——仅提醒，不会自动删除任何文件。

### 操作历史
每一次移入回收站、恢复、永久删除的完整记录（时间、原路径、回收站路径、状态），按时间倒序分页。

## 5. 设置详解

| 设置项 | 说明 | 默认 |
|---|---|---|
| 界面主题 | 跟随系统 / 日间模式 / 夜间模式；「跟随系统」随操作系统深浅色实时切换 | 跟随系统 |
| 项目数据库路径 | SQLite 数据库位置；默认自动管理 | 应用数据目录 |
| 应用回收站路径 | 应用回收站目录，须在本地磁盘 | 应用数据目录/recycle |
| 保护路径规则 | 路径**包含**任一规则的文件禁止标记与删除（如 `Originals`）；分隔符/大小写自动归一（Windows 忽略大小写）。添加规则后可点「预览保护范围」实时查看将保护多少个已索引文件及示例路径 | 空 |
| 排除目录规则 | 路径包含任一规则的目录与文件**不参与扫描**（如 `node_modules`、`venv`），下次扫描生效 | 空 |
| 最小文件大小（MB） | 小于该值的文件不参与重复检测，过滤零字节噪音；0 或留空不过滤 | 0 |
| 回收站保留天数 | 超期未恢复的回收站文件在下次扫描结束时自动永久清理；0 关闭自动清理 | 30 |
| 回收站容量提醒上限（MB） | 回收站实际占用超过该值时在回收站页显示提醒；仅提醒不自动删除；0 不提醒 | 0 |
| 删除前逐字节复核（严格模式） | 开启后，永久删除或移入回收站前把副本与保留副本逐字节比对，彻底排除内容不一致；代价是每个文件多读一遍 | 关 |
| USN 快速扫描（Windows 实验性） | 以管理员身份运行时从 NTFS 变更日志读取文件列表，加速大目录扫描；权限不足时自动回退普通扫描，不影响结果 | 关 |
| 启动时自动增量扫描 | 打开应用即用已保存目录更新索引，可随时取消 | 开 |
| 相似判定阈值 | 「相似照片」视图的 pHash 距离上限（4–20），越小越严格；修改后相似列表立即刷新 | 10 |
| 实时监控扫描目录（实验性） | 开启后监听扫描目录的变化，静置约三秒自动增量扫描；新增扫描目录保存后自动接管 | 关 |
| 预览缓存 | 显示缩略图/预览缓存占用，可一键清理（重新浏览图片时自动重建）；缓存超过 500 MB 时按最旧优先自动淘汰 | — |

修改设置后点击「保存并打开项目」生效。

## 6. 命令行（CLI）

核心库自带 `filelens` 命令（`cargo build --release` 后位于 `target/release/filelens`），适合脚本化或无界面环境：

```bash
filelens init <数据库> <回收站目录>          # 创建/打开项目
filelens scan <数据库> --root <目录> [--root <目录2>]
             [--protect <规则>] [--exclude <规则>]
             [--min-size <字节>]             # 扫描并索引
filelens groups <数据库>                     # 列出重复组及审核状态
filelens approve <数据库> --file-id <ID>     # 标记删除
filelens unapprove <数据库> --file-id <ID>   # 取消标记
filelens trash <数据库> --file-id <ID>       # 移入回收站（须先 approve）
filelens hardlink <数据库> --file-id <ID>    # 转为保留副本的硬链接（须先 approve）
filelens strict-verify <数据库> --enabled    # 开启严格模式逐字节复核（关闭在界面设置）
filelens restore <数据库> --operation-id <ID> # 从回收站恢复
filelens status <数据库>                     # 索引/重复/回收站计数
filelens trash-list <数据库>                 # 列出回收站现存文件
filelens export <数据库> <输出.csv>          # 导出重复组 CSV 报告
```

示例——扫描时排除依赖目录并忽略小文件：

```bash
filelens scan ~/filelens.db --root ~/Photos --root ~/Backup \
  --exclude node_modules --exclude ".cache" --min-size 1048576
```

## 7. 数据位置与备份

| 内容 | Linux | Windows |
|---|---|---|
| 数据库 / 回收站 / 项目指针 | `~/.local/share/local.filelens.desktop/` | `%APPDATA%\local.filelens.desktop\` |
| 缩略图缓存 | `~/.cache/local.filelens.desktop/thumbnails/` | `%LOCALAPPDATA%\local.filelens.desktop\thumbnails\` |

- 数据库是自包含的 SQLite 文件（WAL 模式，同目录可能有 `-wal`/`-shm` 伴随文件，备份时一并复制）。
- 回收站是真实文件副本目录，占用与移入文件等大的磁盘空间。
- **完全卸载**：卸载应用后删除上述两个数据目录即可，不残留其他内容。

## 8. 故障排查

### 常见错误提示对照

| 提示 | 含义与处理 |
|---|---|
| 没有访问权限 | 文件或目录无读取权限；调整权限或用排除规则跳过 |
| 数据库正被其他操作占用 | 稍等片刻重试（WAL 并发保护） |
| 文件内容与索引记录不一致 | 文件在索引后被修改过；重新扫描后再操作 |
| 只有已确认的精确重复副本才能移入回收站 | 需先在审核页「标记删除」 |
| 原位置已存在文件，恢复被拒绝 | 先移走原位置的新文件，再恢复 |
| 该文件已不在索引中 | 刷新列表或重新扫描 |

### 其他问题

- **扫描中某些文件失败**：进度横幅会显示「N 个条目处理失败（点击查看）」，展开可见最近 20 条的文件名与原因（多为权限或文件被占用），扫描完成消息也会报告总数。
- **扫描很慢**：确认已对大目录设置排除规则；增量扫描下未变文件会被快速跳过；>16MB 文件已自动走「先比头部指纹」的两级哈希。
- **WSL2/Linux 启动日志的 EGL/MESA/GBM 警告**：Webview 环境的正常输出，可忽略。
- **AppImage 无法运行**：确认已 `chmod +x` 且系统安装了 FUSE；或改装 deb/rpm 包。
- **扫描后数字与实际不符**：检查排除规则与最小文件大小设置——被排除的文件不会出现在任何统计中。

## 9. 键盘操作

- `Esc`：关闭弹窗（确认框、预览）
- `Enter`：提交输入框（添加目录、保留天数、最小大小）
- `Tab`：在控件间移动，焦点有可见高亮
