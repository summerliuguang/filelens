## 一、项目概况

FileLens 是一个**本地优先**的重复文件整理桌面应用：多目录扫描、BLAKE3 完整内容哈希确认精确重复、感知指纹（照片 dHash / 文档 SimHash）给出相似候选、可恢复的应用回收站。所有扫描、哈希、删除均在用户本机完成，不联网、不上传；「应用回收站 + 操作留痕」构成核心安全模型。

**技术栈**：Tauri 2 + React 19 + TypeScript(strict) + Rust（核心库不依赖 tauri，可独立测试与 CLI 复用）。

**当前状态**：v0.3.0 已完成原改进清单（IMPROVEMENT.md，基于 v0.2.0 的全量审查）中排定的全部 7 个批次，共 27 次提交，20 个核心库单元测试全绿，deb/rpm 安装包出包验证通过。

## 三、功能清单（对照设计文档）

### 已实现 ✅

**扫描与索引**
- 增量扫描（大小+修改时间跳过未变文件）、并行哈希管线、进度/速度/预计剩余时间、可取消
- 扫描进度横幅显示**当前正在处理的路径**；逐文件失败保留最近 20 条样本 + 总数，可展开查看
- 自定义**排除规则**（路径包含匹配，Windows 忽略大小写）与**最小文件大小**（MB，扫描层强制）
- 外部删除的文件在下次扫描标记缺席；失效根目录自动跳过并在完成消息中报告

**检测**
- 精确重复：BLAKE3 + 大小，可自动处理
- 相似照片：dHash ≤4/64，仅供人工查看（带「建议保留」提示）
- 相似文档：TXT/MD/CSV/JSON/XML/HTML 的 SimHash ≤8/64，仅供人工查看
- **两级哈希**：>16MB 文件先比前 64KB 快速指纹，同 (大小， 快速指纹) 桶内才计算全量哈希——同大小的不同大文件不再全量读取
- 音频/视频指纹未接入，检测能力页如实标注

**审核与处理**
- 重复组筛选（路径关键字/最小大小/排序）+ 总数分页；操作后保留已加载页
- 智能标记（保留最新/最旧/最短路径）一键标记
- **硬链接识别**（schema v3）：组内同一物理文件的多个名字打「硬链接」徽章，整组互链时提示「删除副本不会释放空间」；Windows 平台如实降级为不检测
- 缩略图/放大预览（EXIF 方向、磁盘缓存）、系统程序打开、**文件管理器定位**
- 标记删除 → 回收站或直接删除的两步语义；>1GB 文件提示回收站双倍占用
- **CSV 报告导出**（Review 工具栏 + CLI），RFC 4180 转义

**回收站与历史**
- 移入前后哈希校验、恢复防覆盖、永久删除/清空均二次确认
- **批次视图**（schema v4）：一次批量操作的文件在回收站按批次分组展示（操作时间 + 文件数）；批量删除改为核心库单连接执行
- 保留期自动过期（默认 30 天，可关；扫描结束自动清理并在消息中报告数量）
- 全量操作留痕（移入/恢复/删除），按时间倒序分页

**体验与工程**
- 全页面切换保持现场（筛选、勾选、滚动不丢）
- 按操作细化的 busy 状态（按钮只对自己所属操作禁用）
- toast 通知（成功自动消失、错误手动关闭）、Escape 关闭弹窗、focus-visible 焦点态
- 设计令牌（`:root` CSS 变量统一强调色/面板色/弱文本色/圆角）
- CI（核心测试 + 类型检查 + 命令层检查）、Schema v1→v2 自动迁移框架

### 未实现（Backlog 💭）

空文件夹/零字节文件视图、回收站容量上限提醒（批次视图已实现）、缩略图 LRU 上限、相似视频/音频、完整保留评分模型、批量恢复/批量永久删除（按批次）。

## 五、架构说明

```
src/main.rs            核心库（2746 行）：扫描管线、BLAKE3/快速哈希、相似检测、
                       回收站、安全链、Schema 迁移、CLI、全部单元测试。不依赖 tauri。
src/lib.rs             核心库导出清单
src-tauri/src/main.rs  薄命令层（1061 行）：#[tauri::command]、serde 结构体、
                       缩略图渲染与缓存、后台扫描任务槽
src/main.tsx           App 状态与外壳（509 行）
src/ui/views.tsx       九个页面视图
src/ui/components.tsx  ConfirmDialog / PreviewModal / Empty / ScanProgress
src/lib/{types,format} 跨层类型镜像（snake_case 对齐）与格式化/错误翻译
```

**文件操作安全链**（所有删除类命令复用，历史上绕过校验曾是安全后门）：
查索引 → 拒绝受保护路径 → 删除前重哈希比对 → 原子移动（rename 失败走 copy+校验+删源）→ `operations` 表留痕 → 置 `present=0`。

**Schema 演进**：`ensure_initialized` 读取 `schema_version`，低于当前版本则按 `MIGRATIONS` 数组逐步事务升级（v2 新增 `files.quick_hash` 列与 `(size, quick_hash)` 索引），高于当前版本拒绝打开。老库升级无需人工干预。

**SQLite 约定**：每连接 `journal_mode=WAL` + `busy_timeout=5000`；后台扫描采用 `Mutex<Option<ScanTask>>` 任务槽 + `AtomicBool` 协作取消 + 前端 500ms 轮询。

## 六、已知限制

1. **AppImage 打包**：构建环境的 linuxdeploy 外部工具偶发失败；deb/rpm 与裸二进制验证不受影响，发布 Windows NSIS 交叉编译路径亦不受影响。
2. **相似检测只读**：相似照片/文档是视觉/文本近似，误报率高于精确哈希，设计上仅允许人工逐个确认后处理，不提供自动清理。
3. **两级哈希的空扫描场景**：孤立大文件先以 `q:` 标记哈希入库（不参与分组），孪生文件出现时自动晋升为全量哈希；这意味着「先扫到孤立大文件、后续新增相同文件」的成组要等到第二次扫描。
4. **工程残留**：App 状态仍为多个 useState（未收拢为 reducer）、前端 invoke 未做集中封装、圆角/字号收敛未完成——均已记录在 IMPROVEMENT.md。

## 七、下一步建议（优先级从高到低）

1. **真实规模验证**：在 10 万+ 文件的真实目录上实测扫描耗时与两级哈希收益（DESIGN.md §12 的性能目标尚无实测数据）。
2. **硬链接检测**（P2-3）：避免「删除硬链接的另一名字却释放 0 空间」的用户困惑，Unix 记录 (dev, inode) 即可起步。
3. **回收站批次视图**（P2-8）：operations 表已有时间索引，按批次分组展示成本低。
4. **空文件夹/零字节检测**（P2-5）：接入现有 detector 框架。
5. **前端状态收拢**：useReducer + `lib/api.ts` 集中 invoke，根治 snake_case 对齐隐患。
